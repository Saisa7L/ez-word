## 测试缺口

- 已有 30 项测试：24 项数据/用例测试，6 项任务 reducer/展示/路由测试。覆盖 v0 → v18 真实迁移、schema 校验、迁移回滚、存档兼容与安全、完成页统一结算、v18 索引、`TaskWord` mapper、三种任务启动用例、任务状态机和阶段路由。
- 没有覆盖页面交互的单元测试。
- 没有组件渲染测试。
- 没有端到端 UI 测试。
- 没有循环依赖和未使用导出的自动化检查。
- 真机流程仍依赖人工验收。

因此，涉及数据库事务、存档、导航或原生能力时，仅通过类型检查和打包不能证明行为完全正确。

## 技术债优先级

### 已解决：P0 数据与任务主链路

- 迁移已改为版本注册表，并在同一主连接事务中执行。
- `user_version` 在每一步迁移后写入，失败会整体回滚。
- `ALTER TABLE` 已使用列存在检查，兼容旧实现留下的部分迁移状态。
- 启动和设置保存会确保 `app_settings` 单行存在。
- 任务返回键改为焦点级监听，完成页有独立返回守卫并使用 `replace`。
- 填空和听力错误只累计在内存，退出任务不改变单词状态；完成页通过 `completeTaskSession` 单事务统一写库。
- 同一单词同时来自填空和听力的错误来源会合并，`wrong_count` 每次任务只增加一次。
- 存档读取使用事务，恢复使用同一主连接事务，并校验大小、字段范围、图片 URI 和引用完整性。
- v10-v16 存档可迁移旧主题与资料默认值，导出文件名显式带 `.json`。
- 主题初始化、错题回顾启动和图片选择补齐错误处理。
- 后续仍需补真实旧版本数据库 fixture，并在真机验证返回键、SAF、相册和 TTS。

### P0：存档 schema 与数据库 schema 双维护

当前已通过 `src/database/schema.ts` 统一当前字段、存档字段、恢复顺序，并在迁移后校验真实表结构。真实 SQLite 测试会执行 v0 → v18 迁移，因此迁移 SQL 虽然是手写，但结果已被测试锁定。

建议：

- 保持 schema 定义、迁移 SQL 和校验三者同步。
- 后续增加更多旧版本存档样例和迁移回归数据。

## 推荐重构顺序

1. word-import 解析和入库用例的进一步分层。
2. 页面交互测试和组件渲染测试。
3. 列表空态、加载骨架和剩余样式复用。
4. 更多旧版本存档和错误数据回归样例。

## 重构护栏

- 不改变已经收口的 P5 视觉规则。
- 不新增功能。
- 新增组件、样式变体、Hook、工具或服务方法前，先搜索同类实现并复用；只有现有模式不适用时才新增。
- 不跨多个业务域同时重写。
- 每次只移动一个内聚区块。
- 先补契约和测试，再移动事务代码。
- 页面拆分后保持路由和用户操作路径不变。
- 每批提交必须可独立回滚。

## 新 AI 修改代码前必须确认

1. 改动属于哪个模块和业务不变量。
2. 是否触碰 SQLite 事务。
3. 是否影响存档字段或版本兼容。
4. 是否改变页面导航或返回行为。
5. 是否需要真机验证原生能力。
6. 自动检查能覆盖什么，不能覆盖什么。
