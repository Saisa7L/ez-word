# 质量与技术债

最后更新：2026-10-19 18:12

## 当前质量门槛

每次代码整理至少执行：

```powershell
npm run typecheck
npm run lint
npx expo export --platform android --output-dir .expo/check
```

涉及 Expo 配置或依赖时增加：

```powershell
npx expo config --type public
npx expo-doctor
```

## 已具备的自动验证

- TypeScript 类型检查
- ESLint
- Expo 配置解析
- Android Metro 打包和资源引用检查
- 文档引用存在性检查

## 测试缺口

- 没有统一单元测试框架和测试脚本。
- 没有可重复执行的 SQLite 集成测试套件。
- 没有组件渲染测试。
- 没有端到端 UI 测试。
- 没有循环依赖和未使用导出的自动化检查。
- 真机流程仍依赖人工验收。

因此，涉及数据库事务、存档、导航或原生能力时，仅通过类型检查和打包不能证明行为完全正确。

## 高内聚与低耦合现状

| 模块 | 内聚性 | 耦合风险 | 判断 |
|---|---|---|---|
| `database` | 较高 | 接受 SQLite 连接和少量常量 | 职责清晰 |
| `services` | 较高 | 文件、网络、TTS、SecureStore 各自独立 | 边界清晰 |
| `features/daily-task` | 较高 | 依赖 WordRecord 和设置类型 | 合理 |
| `features/archive` | 中等 | 直接依赖完整数据库 schema | 高风险 |
| `features/word-import` | 中等 | 同时做文件 I/O、解析和入库 | 可拆分 |
| `components` | 较高 | 依赖主题和部分业务显示类型 | 基本合理 |
| `app/settings` | 偏低 | 页面直接编排仓库、表单和弹层 | 需拆分 |
| `app/daily-task` | 中等 | 页面直接调用错误记录和完成仓库 | 可接受但需契约 |
| `hooks` | 较高 | 依赖 SQLite 调用方传入 | 新 Hook 方向正确 |

## 技术债优先级

### P0：存档 schema 与数据库 schema 双维护

`features/archive/archiveSnapshot.ts` 单独保存表名、字段、旧版本默认值、删除和插入顺序。数据库字段变化时容易漏改。

建议：

- 建立单一 schema 描述。
- 迁移、存档字段和恢复 SQL 从同一来源生成或校验。
- 增加存档 round-trip 和旧版本兼容自动测试。

### P1：超大设置页面

| 页面 | 行数级别 | 问题 |
|---|---:|---|
| `settings/profile.tsx` | 约 430 | 已完成展示、编辑和外观弹窗拆分，保留数据和保存编排 |
| `settings/daily-task.tsx` | 约 170 | 已完成表单区块和通用步进器拆分 |
| `settings/ai.tsx` | 约 280 | 已完成 Key 和例句生成区块拆分 |
| `settings/import.tsx` | 约 590 | 文件、导入、清空、说明弹层混合 |

建议按页面区块提取组件和表单 Hook，不直接按行数机械拆分。

### P1：页面直接调用仓库

简单列表读取可保留。涉及以下情况应下沉：

- 多个仓库组合。
- 事务和状态联动。
- 失败后的统一恢复。
- 多个页面复用同一流程。

### P2：word-import 边界混合

当前模块同时负责：

- 文件选择和读取。
- CSV 解析。
- 数据库导入编排。

建议拆成纯解析、文件服务和导入用例，便于测试。

### P2：SQL 字段列表重复

`WordRecord` 的查询字段在多个仓库重复出现。字段变化时需要同步多处。

建议建立共享字段列表或查询构造器，但不能牺牲 SQL 可读性。

### P2：展示辅助函数重复

- 听力速度格式化存在细微差异。
- 任务标题已统一，仍有局部文案分支。
- 列表空态和加载骨架样式重复。

### P3：主题样式重复

多个页面重复定义相同按钮、列表行和弹层样式。优先在出现第三个相同场景时抽取，避免过早抽象。

### P3：测试数据覆盖有限

当前 CSV 样例覆盖基础导入、任务、复习和 AI 例句，但缺少错误行、极端旧存档和损坏数据样例。

## 推荐重构顺序

1. 存档 schema 单源化和自动测试。
2. word-import 拆分。
3. SQL 字段定义和展示辅助函数整理。
4. 样式复用评估。

## 重构护栏

- 不改变已经收口的 P5 视觉规则。
- 不新增功能。
- 不跨多个业务域同时重写。
- 每次只移动一个内聚区块。
- 先补契约和测试，再移动事务代码。
- 页面拆分后保持路由和用户操作路径不变。
- 每批提交必须可独立回滚。

## 新 AI 修改代码前必须确认

1. 改动属于哪个模块和业务不变量。
2. 是否触碰 SQLite 事务。
3. 是否影响存档字段或版本兼容。
4. 是否改变页面导航或返回行为。
5. 是否需要真机验证原生能力。
6. 自动检查能覆盖什么，不能覆盖什么。
