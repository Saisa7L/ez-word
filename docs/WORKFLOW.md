# 项目协作工作流

最后更新：2026-10-16

## 阶段推进

每个阶段开始时必须先说明：

1. 本阶段目标。
2. 本阶段要做的事。
3. 完成标志。

得到用户确认后，才进入下一阶段。

## 需求澄清范围

规划阶段只确认：

- 页面解决什么问题。
- 页面之间如何跳转。
- 功能输入和输出是什么。
- 第一版需要哪些页面和状态。
- 哪些功能明确不做。

规划阶段不提前纠缠：

- 音频播放几遍。
- 每次间隔几秒。
- 一页显示几条数据。
- 动画时长和过渡方式。
- 需要实际运行后才能确定的参数。

这些细节在对应功能开始写代码前，用“本次需要锁定的细节”集中确认，每轮最多 5 项。

## 单个功能流程

每个功能按以下顺序执行：

1. 需求。
2. 本次需要锁定的细节。
3. 实现思路。
4. 代码。
5. 验证方法。
6. 常见错误。
7. 类型检查、Lint 和 Expo Doctor。
8. 更新上下文文档。
9. Git 提交。

## UI 图片规则

- 标准 UI 使用无标注图片。
- 如果需要解释交互，使用带中文标注的图片。
- 标注图用于说明按钮和区域含义，不视为新页面。
- 如果页面元素没有识别清楚，先询问，不自行猜测。
- 页面流程确认后，具体尺寸、间距和交互参数在开发该页面时再确定。

## 安装和依赖

- 安装软件、服务或依赖前，先确认安装位置。
- 项目依赖使用 `npx expo install` 选择 Expo SDK 57 兼容版本。
- 不运行 `npm audit fix --force`。
- 不根据安全审计结果把 Expo 降级到旧版本。

## 报错处理

用户发送报错时：

1. 先判断错误类别。
2. 找根因。
3. 给最小改动修复步骤。
4. 说明修复后的验证方法。
5. 不轻易重装环境或推倒重来。
